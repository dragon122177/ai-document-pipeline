# Contributing

1. Create a focused branch from `main`.
2. Keep API fields backward-compatible or document the migration.
3. Add tests for pipeline, permission, or UI behavior that changes.
4. Run `make test` and `make build`.
5. Open a pull request with the problem, approach, validation, and risks.

Do not commit `.env`, `.data/`, uploaded documents, generated builds, virtual
environments, or dependency directories.
